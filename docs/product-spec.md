# SF6-Rating — Product Spec

Status: Reviewed — Ready for Implementation Planning
Product: SF6-Rating

---

# 1. Product Overview

## Product Name

SF6-Rating

## One-Line Description

Street Fighter 6で、実力の近いプレイヤーと素早く3先（FT3）を行い、その結果から独自レーティングを競うためのWebサービス。

## Problem

Street Fighter 6の通常のランクマッチでは、短い対戦単位が中心となるため、同程度の実力を持つ相手とまとまった3先を継続的に行う機会を作りにくい。

また、自分で3先相手を探そうとすると、

- 相手探しに時間がかかる
- 相手との実力差が分かりにくい
- 募集場所が分散する
- 継続的に実力を比較する仕組みがない

といった問題がある。

## Solution

SF6-Rating独自のプレイヤーレーティングを利用して、近い実力・近い地域のプレイヤー同士をマッチングする。

ユーザーは対戦待機状態になるだけで、

- 自動マッチング
- 募集中プレイヤー一覧からの手動選択

の両方を利用できる。

マッチ成立後はStreet Fighter 6の「カスタムルームマッチ」を利用して3先を行い、双方が結果を報告する。

一致した結果だけを正式な対戦結果として確定し、レーティングへ反映する。

# 2. Target User

## Primary User

Street Fighter 6をプレイするすべてのプレイヤー。

初心者からMaster帯などの上級者まで特定ランクに限定しない。

初期ローンチでは日本のプレイヤーを中心とするが、英語UIにも対応し、海外ユーザーも利用可能とする。

## User Situation

ユーザーが、

- ランクマッチとは違うまとまった対戦をしたい
- 実力の近い相手と3先したい
- 3先での自分の実力を測りたい
- ランキングを競いたい

と考えたときに利用する。

SF6をPC・PlayStation等で起動しながら、スマートフォンまたはPCブラウザでSF6-Ratingを利用することを想定する。

## User Needs

ユーザーが最も必要としているものは、

**「実力の近い相手を短時間で見つけ、すぐ3先を始められること」**

である。

---

# 3. Product Goal

実力の近いSF6プレイヤー同士が、簡単かつ継続的に3先できる場所を作る。

レーティングは単純な1試合ではなく3先セットの結果を評価することで、よりまとまった対戦におけるプレイヤーの実力を表す。

## User Outcome

ユーザーはSF6-Ratingを利用することで、

- 自分と近い実力の相手を見つけられる
- すぐ3先を開始できる
- 継続的に3先をプレイできる
- 3先での自分の実力をレーティングとして確認できる
- 他プレイヤーとの順位を比較できる
- 自分の成長や対戦履歴を確認できる

ようになる。

## Business / Project Outcome

MVPでは収益化を主目的としない。

最優先で検証するのは、

**「実力の近い相手と3先できるサービスに実際の需要があり、ユーザーが繰り返し利用したいと思うか」**

である。

# 4. Core User Experience

基本的なユーザーフローは以下。

1. SF6-Ratingを開く
2. アカウントを作成する
3. SF6のユーザーコード・プレイヤー情報を登録する
4. 現在のメインキャラクターとSF6内ランク / MRを登録する
5. 仮レーティングが設定される
6. 「対戦相手を探す」を開始する
7. 対戦待機状態になる
8. 自動マッチングの対象になる
9. 同時に募集一覧にも表示される
10. 自動マッチ、または募集一覧からの選択によって対戦成立
11. Match Roomへ移動する
12. システムがカスタムルーム作成担当を決める
13. 必要なら作成担当を交代する
14. 作成担当がSF6内でカスタムルームを作成する
15. 相手がプレイヤーネームまたはユーザーコードを利用して合流する
16. 3先を行う
17. 必要に応じてセット中にキャラクターを変更する
18. どちらかが3勝した時点で終了する
19. 両プレイヤーがSF6-Ratingに結果を入力する
20. 両者の報告内容が一致する
21. 対戦結果が確定する
22. レーティングと戦績が更新される
23. プロフィール・ランキングへ反映される

# 5. Core Features

## Feature 1 — Account & Player Profile

概要:

SF6-Ratingのアカウントを作成し、SF6プレイヤー情報を登録する。

目的:

レーティング・戦績・対戦履歴を一人のプレイヤーに紐付ける。

主な情報:

- ユーザー名
- プロフィールアイコン
- SF6プレイヤーネーム
- SF6ユーザーコード
- 地域
- 現在のメインキャラクター
- SF6ランク / MR
- SF6-Ratingレート
- 戦績
- 対戦履歴

SF6ユーザーコードの厳格な本人確認はMVPでは必須にしない。

---

## Feature 2 — Matchmaking

概要:

実力の近いプレイヤー同士を素早くマッチさせる。

目的:

SF6-Ratingの中心価値である「近い実力の相手とすぐ3先する」を実現する。

マッチングでは、

- レーティング差
- 地域
- 待ち時間

を考慮する。

最初は近いレート・近い地域を優先し、待ち時間が長くなるにつれて許容条件を段階的に広げる。

---

## Feature 3 — Waiting Pool / Player List

概要:

自動マッチングと募集一覧で同じ待機プレイヤープールを使用する。

目的:

ユーザー人口を複数のモードへ分散させず、対戦成立率を高める。

共通Available Poolを使用するが、entry modeごとにeligibilityを分ける。

- Quick Match: auto-match ON、募集一覧表示可
- Find Opponent受付中: auto-match OFF、募集一覧表示のみ
- 閲覧のみ: Poolへ掲載せず、auto-match対象外

募集一覧から相手を選択した場合、相手の承認を待たず即マッチ成立とする。

募集一覧では、

- ユーザー名
- プロフィールアイコン
- レーティング
- 地域
- 待機時間

などを表示できる。

ただしレート戦のマッチ成立前には、

- 使用予定キャラクター
- メインキャラクター
- キャラクター使用率
- その他キャラクターに関する情報

を表示しない。

---

## Feature 4 — Match Room

概要:

マッチ成立後、SF6内で対戦を開始するまでを支援する専用画面。

目的:

マッチ成立後の迷いや待ち時間を減らす。

表示情報:

- 対戦相手
- プレイヤーネーム
- SF6ユーザーコード
- レーティング
- カスタムルーム作成担当
- 対戦状態

システムが片方をカスタムルーム作成担当として自動指定する。

必要な場合は作成担当を相手へ交代できる。

自由入力チャットはMVPでは提供しない。

代わりに、

- ルームを作成しました
- 参加しました
- 見つかりません
- もう一度お願いします
- 少し待ってください

などの定型メッセージを利用できる。

---

## Feature 5 — FT3 Match

概要:

Street Fighter 6内で3先を行う。

基本ルール:

- 同じ相手とのセットで先に3ゲーム勝利したプレイヤーが勝者
- セット途中のキャラクター変更は自由
- 1ラウンドの制限時間は60秒
- その他のゲーム内設定は原則としてSF6の標準設定に従う。ただし、Round Timeのみ標準の99秒ではなく60秒とする
- Match RoomではCustom Room作成担当へ `Round Time: 60 seconds` を明示する
- SF6-Ratingはゲーム内設定を自動検証できないため、60秒設定はHostと参加者が従う運用ルールとして扱う

SF6-Ratingはゲームそのものを実行せず、SF6のカスタムルームマッチを利用する。
このルール変更はResult ReportingおよびRating計算ロジックへ影響しない。

---

## Feature 6 — Result Reporting

概要:

対戦終了後、両プレイヤーがそれぞれ結果を報告する。

目的:

一方的な虚偽報告によってレーティングが変更されることを防ぐ。

例:

Player A:
3-1で勝利

Player B:
1-3で敗北

両者の報告が整合している場合のみ対戦結果を確定する。

---

## Feature 7 — Rating System

概要:

3先セットの勝敗を利用して独自レーティングを計算する。

レーティングはキャラクター単位ではなく**プレイヤー単位**とする。

キャラクター変更を含めた3先全体での対応能力もプレイヤーの実力として扱う。

レーティング計算ではセットスコア差を使用しない。

3-0、3-1、3-2のどれであっても「1セット勝利」として評価する。

スコアは戦績データとして保存する。

### Rating Philosophy

相手とのレート差から期待される結果との差を強く評価する。

- 格上に勝つ → 大きく上昇
- 同格に勝つ → 標準的に上昇
- 格下に勝つ → 少し上昇
- 格上に負ける → 少し下降
- 同格に負ける → 標準的に下降
- 格下に負ける → 大きく下降

SF6の通常ランクマッチよりも、相手とのレート差をレート変動へ強めに反映する。

### Rating Formula

Elo系をベースとし、プレイヤーAの期待勝率と更新後レートを次の式で計算する。

```text
E_A = 1 / (1 + 10^((R_B - R_A) / 250))
R'_A = R_A + 64 × (S_A - E_A)
```

- レーティングの中心値: `1500`
- 期待値スケール: `250`
- K値: `64`
- 勝利時のスコア `S_A`: `1`
- 敗北時のスコア `S_A`: `0`
- 同レート同士の通常変動: `±32`

計算結果の整数丸め、Clamp、境界は[Rating System Feature Spec](./features/rating-system.md)をSource of Truthとする。

## Feature 8 — Placement

概要:

新規プレイヤーを短期間で適正レートへ配置する。

初期レートは、

**ユーザーが登録した現在のメインキャラクターのSF6ランク / MR**

を参考に設定する。

初期レートは正確な実力判定ではなく、Placementの開始地点として扱う。ランク / MRから初期レートへの暫定換算は以下とする。

| SF6メインキャラのランク | 初期レート基準値 |
| --- | ---: |
| Rookie | 900 |
| Iron | 1000 |
| Bronze | 1100 |
| Silver | 1200 |
| Gold | 1300 |
| Platinum | 1450 |
| Diamond | 1650 |
| Master | 1850 |

ランク内に1〜5の段階がある場合は、基準値へ `-40 / -20 / ±0 / +20 / +40` を加える。

MasterはMRを使い、次の式を初期案とする。

```text
初期レート = 1850 + 0.75 × (MR - 1500)
```

Masterの初期レートには過度に低くならないための下限を設ける。下限の具体値はFeature Specで検証する。

Placementは新規登録時の最初の**10セット**とし、変動倍率を段階的に下げる。

| セット数 | 通常変動に対する倍率 |
| --- | ---: |
| 1〜3セット目 | 2.0 |
| 4〜7セット目 | 1.5 |
| 8〜10セット目 | 1.25 |
| 11セット目以降 | 1.0 |

Placement中の1セットあたりの変動量には暫定で `±96` の上限を設け、実装前のシミュレーションで検証する。

配置期間中もマッチングは可能だが、ランキング対象外とする。10セット完了時点でPlacementを終了し、正式ランキングへ参加する。Placementは原則として新規登録時のみ実施し、既存ユーザーは新シーズン開始時に再実施しない。

---

## Feature 9 — Rematch / Rated Limit

概要:

同じプレイヤーとの繰り返し対戦によるレート操作を抑制する。

同一プレイヤーとのレート対象3先は**24時間に1セットまで**とする。

24時間の起点は、両者の報告が一致しRated対戦結果が確定した時刻とする。その時刻から24時間が経過するまで、同じ2プレイヤー間の追加対戦はアンレート扱いになる。

その後も対戦自体は自由に行える。アンレート戦ではレーティングは変動せず、アンレート戦を行っても24時間の期限は延長・リセットしない。

Player pairは順序非依存のcanonical pair keyで識別する。Rated / UnratedはClient指定だけで決めず、Match作成Transaction内でpair単位Lockまたは同等の直列化を行い、cooldown判定とMatch作成を同一Transactionで確定する。

対戦履歴・戦績として保存するかどうかの詳細はFeature Specで決定する。

## Feature 10 — Public Profile

ユーザーごとの公開プロフィールを提供する。

表示候補:

- ユーザー名
- アイコン
- 現在レート
- 勝敗
- 勝率
- 3-0 / 3-1 / 3-2等のセット結果
- 対戦履歴
- シーズン成績

プロフィール上でのキャラクター関連情報は将来的に利用できる余地を残す。

ただしレート戦のマッチ成立前にはキャラクター情報を表示しない。

---

## Feature 11 — Ranking

現在シーズンのプレイヤーランキングを表示する。

基本順位はSF6-Ratingレートを基準とする。

配置期間中のプレイヤーはランキングへ掲載しない。

---

## Feature 12 — Seasons

レーティングはシーズン制とする。

シーズン終了時には、

- 最終レート
- 最終順位
- シーズン戦績

などを保存する。

1シーズンは**3か月**とする。

次シーズン開始時には完全リセットではなく**ソフトリセット**を行い、前シーズンのレートと中心値1500との差を30%圧縮する。

```text
新シーズンレート = 1500 + 0.7 × (前シーズン終了レート - 1500)
```

これにより前シーズンの実力差を残しながら、ランキングを中央方向へ圧縮する。既存ユーザーは新シーズン開始時にPlacementを再実施しない。

---

## Feature 13 — Admin

MVPには最小限の運営管理画面を用意する。

運営は最低限、

- dispute状態の対戦確認
- 両プレイヤーの報告内容確認
- 正しい対戦結果の確定
- 対戦の無効化
- 放置履歴の確認
- 問題行動履歴の確認
- 必要に応じた一時的なマッチング制限

を行える。

# 8. Product Rules

1. レーティングはプレイヤー単位で管理する。

2. 3先セット中のキャラクター変更は自由。

2-a. Rated FT3の1ラウンドの制限時間は60秒とする。その他のゲーム内設定は原則SF6標準とするが、Round Timeのみ標準の99秒ではなく60秒とする。SF6-Ratingはこの設定を自動検証せず、Hostと参加者が従う運用ルールとして扱う。

3. レート戦マッチ成立前に使用キャラクター関連情報を表示しない。

4. 募集一覧ではユーザー名・アイコン・レート・地域などを表示できる。

5. 募集一覧へ表示されているユーザーは手動選択可能だが、Find Opponent受付中は自動マッチング対象にしない。

6. 募集一覧から選択された場合、追加承認なしでマッチ成立する。

7. 自動マッチングと募集一覧は同じ待機プレイヤープールを利用する。

8. マッチングではまず近いレート・地域を優先する。

9. 待ち時間が増えるほどマッチング条件を緩和する。

10. 対戦結果は両プレイヤーの報告が一致した場合のみ確定する。

11. レーティングは3先セットの勝敗によって変動する。

12. 3-0 / 3-1 / 3-2等のスコア差はレーティング計算へ直接使用しない。

13. レーティングは中心値1500、期待値スケール250、K値64のElo系計算を使用する。

14. 同一プレイヤーとのレート対象対戦は、Rated結果の確定時刻から24時間に1セットまで。

15. 上限後もアンレート戦として対戦可能であり、アンレート戦によって24時間の期限は変化しない。

16. 配置期間は新規登録時の10セットとし、配置期間中のプレイヤーはランキング対象外。

17. Placementの変動倍率は1〜3セット目が2.0、4〜7セット目が1.5、8〜10セット目が1.25、以降が1.0。

18. ランキングは3か月単位のシーズン制とする。

19. シーズン変更時には、1500との差を30%圧縮するソフトリセットを行う。

20. 既存ユーザーは新シーズン開始時にPlacementを再実施しない。

21. 単発の放置では重いペナルティを課さない。

22. 短期間に放置を繰り返すユーザーにはマッチング制限を行える。

23. モバイル・PCの両方で主要機能を利用できる。

24. Match `status`は`matched | room_setup | reporting | disputed | completed | cancelled`だけを使用する。

25. 正式な勝敗がある終了は`completed`、勝敗なしの終了は`cancelled`とする。終了理由は`resolution_type`、後日無効化は`result_validity`、Rating処理は`rating_status`で分離する。

26. `matched | room_setup | reporting | disputed`のRated Matchを持つPlayerは新しいRated Matchへ参加できず、`completed | cancelled`でgateを解除する。

27. Current Season中のCompleted Match無効化はRatingと競技Statsを同じDomain Actionで補正し、Placement countは巻き戻さない。Completed SeasonのFinal Snapshotは変更しない。

# 9. Edge Cases

## Result Mismatch

両プレイヤーの結果報告が一致しない場合:

1. 結果を確定しない
2. 両者へ再入力を要求
3. 再度不一致の場合はdispute状態にする
4. 運営が確認
5. 正しい結果を`completed + admin_result`で確定、または`cancelled + admin_invalid_no_rating`で終了

## Player Does Not Respond

マッチ成立後に相手が一定時間反応しない場合:

- 対戦をキャンセル
- レーティングは変更しない
- 放置履歴を記録する
- 単発では重いペナルティを課さない
- 短期間に繰り返した場合は一定時間マッチングを制限する

## Player Leaves During Match

対戦途中で一方が離脱した場合の正式な勝敗処理はFeature Specで定義する。

## Network Error

サイトまたはSF6側で通信トラブルが発生した場合、誤ったレーティング変更が起きないことを優先する。

## Duplicate Submission

同じ対戦結果が複数回送信されても、レーティング変更は一度だけ行う。

## Same Opponent

同じ2プレイヤー間のRated結果が確定した時刻から24時間以内に再度対戦した場合はアンレート扱いとする。アンレート戦を行っても24時間の期限は延長・リセットしない。

## Placement Player

配置期間中でも通常プレイヤーとのマッチングは可能だが、ランキングには表示しない。

## Concurrent Match

同じユーザーが複数のレート戦へ同時参加できないようにする。

- 3先を実施できる
- 双方が結果を入力できる
- 結果一致時のみ試合を確定できる
- 正しくレーティングが更新される

- Placementを終了できる
- 正式ランキングへ参加できる
- 公開プロフィールを確認できる
- ランキングを確認できる
- 同一相手への24時間レート制限が機能する

# 11. Constraints

- 個人開発を前提とする
- コア体験の品質を優先する
- MVP外の機能を増やしすぎない
- 初期コストを抑える
- Webサービスとして提供する
- スマートフォンとPCの両方へ対応する
- UXはモバイルファーストとする
- 日本を初期の中心市場とする
- 日本語・英語に対応する
- 海外展開を阻害しない構造にする
- SF6そのものとの直接連携を前提にしない
- ユーザーの手動結果報告でも信頼できるレーティングを維持する
- 重要なレーティング操作はサーバー側で安全に処理する必要がある

# 11.1 Cross-Spec Resolved Decisions

- Season終了30分前から新規Rated Matchmakingを停止する。
- Season終了時点でRating未確定の旧Season Rated Matchは`status=cancelled`、`resolution_type=season_boundary_no_rating`で終了し、後からRated結果として復活させない。Dispute / Incidentの監査記録は保持できる。
- Current Season中のCompleted Rated Match無効化は、Compensating Rating Correction、Rated W/LとMatch Countの除外、Win Rate再計算、score breakdown除外、Ranking更新、Public Match History非表示を同じDomain Actionで行う。Placement countは巻き戻さない。
- completed SeasonのFinal Rating / Ranking / Stats Snapshotは変更しない。
- Progressive Restrictionは`incident.confirmed_at`基準のrolling 30 daysを使う。同一Matchにつき`1 user × 1 match`で最大1 Reliability Strikeとする。
- MVP Incident Typesは`no_show | abandonment | result_nonresponse | match_completion_failure`とする。
- Strike段階は1=Warning、2=1時間停止、3=24時間停止、4+=Admin Reviewで最大7日とする。無効化されたIncidentは将来の集計から除外し、既発行RestrictionはAdminの明示的Revoke / Adjustでのみ変更する。
- Rating丸め、Clamp、Master初期Rating境界、同順位、Soft Reset丸め、Public Profileのキャラクター非公開、Dispute evidence、Progressive Restriction、Compensating Correctionは関連Feature Specsで解決済みである。
